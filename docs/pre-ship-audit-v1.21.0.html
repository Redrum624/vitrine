What passed (the record)

The audit is as much a record of what's correctly bounded as of what isn't — nine dimensions verified clean:

  • Electron window config: contextIsolation:true, nodeIntegration:false, sandbox:true, webSecurity:true on BOTH windows.
  • A real CSP meta (script-src 'self' 'wasm-unsafe-eval', object-src 'none', no unsafe-inline for scripts); deny-by-default setWindowOpenHandler; structured-origin will-navigate.
  • Every destructive IPC routes through validateWritePath (path.resolve collapses traversal); hostile-input parsers (rawMetadata, baseCache) bounds-check every offset.
  • No hardcoded secrets/keys anywhere in src/electron/scripts.
  • In-memory image cache: dual-budget LRU (500MB sized + 700MB base), independently evicted, oversized entries refused.
  • Disk base cache: 2GB LRU whose in-memory index is budget-bounded (not open-count); temp files cleaned on init AND mid-session failure.
  • GPU pipeline: singleton holds one image's textures — setSource deletes the previous before uploading; mask cache LRU-capped at 32.
  • Per-image state released at the switch choke point: checkpoints capped at 200 + reset per path; restoreStack + bakedBaseState cleared; single-slot debounce timers.
  • The unsaved-close modal + its capture-phase Esc listener are removed on all four dismissal paths; onnx sessions are resident singletons by design (fixed cost, not growth).

Note: several heavy "accumulator" services (BackgroundProcessing, MultiThreading, Pyramid, MemoryStreaming, PerformanceProfiler) are dead code — never imported, tree-shaken from the bundle, their timers never run. Candidate purge.

Write-path policy — accepted residual limitations (v1.22.0)

The write-file deny-list survived three adversarial passes; it now fails closed — it enumerates the allowed roots (drive-letter + normal UNC share) and rejects every other root form (Volume-GUID / GLOBALROOT device paths, verbatim-namespace prefixes, trailing-dot/space and 8.3/symlink parents), at the pure validator without relying on realpath. The following residuals are documented and accepted for a local desktop app whose threat model requires a prior renderer compromise:

  • Leaf-symlink/junction TOCTOU — realpath resolves only the parent; a pre-existing leaf symlink into a sink is followed by the write. Requires symlink-create privilege (admin / Developer Mode); backstopped by the extension allow-list for the two file-drop handlers.
  • Extension allow-list covers 2 of 5 write handlers — write-image-metadata / write-image-rating / trash-items rely on the deny-list alone (they operate on existing images / the recycle bin).
  • UNC shares are admitted by design — legitimate exports to \\nas\… must work; \\localhost\C$-style admin-share aliasing is elevation-gated, outside the non-elevated-renderer model.
  • Inert guard-passers — reserved device names (NUL/CON) and the bare raw-volume handle (\\.\C:) pass the root check but address null/console/raw-volume (admin-gated), never a filesystem sink; the extension allow-list blocks them on the file-drop handlers.
  • The deny-list is an enumerated set (system dirs + Startup + PowerShell profiles + ~/.ssh), not every Windows persistence vector — deliberately a deny-list so arbitrary user export folders stay writable; the extension allow-list is the defense-in-depth layer.
