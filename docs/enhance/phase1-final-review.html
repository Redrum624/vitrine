The headline finding

The 14 unit/integration tasks are individually correct and well-tested. The Sharpen path is fully working and merge-ready — it runs through the pipeline as module params, so it applies on the live canvas and on export at full resolution. The Upscale path is broken at the integration seam: it bakes enlarged pixels into the in-memory working image, but the app's export, persistence, and History are all param-based and re-decode the original file — so the upscaled pixels never reach any durable output.

Critical (must fix before Upscale ships)

#IssueWhy it matters
C1 Upscale result is display-only — lost on Export & reload. ExportDialog.tsx:224 re-decodes the source file and re-runs the pipeline with current params. applyUpscale bakes the ×scale pixels into imageService.currentImage then resetAllModules() — and the export path never reads currentImage. Persistence (EditPersistenceService.serialize) stores params only, no pixels/dims. After a ×2 upscale the user sees a 2× enhanced canvas, exports, and gets the native-resolution un-enhanced original. The feature produces no durable output.
C2 History can't represent the upscale; "Enhanced ×N" checkpoint is mislabeled & non-functional. checkpointService.record() runs after resetAllModules(), so it serializes neutral state; the label diff yields "Multiple adjustments", not "Enhanced ×N". Restoring can't recover native size/pixels; restoring a pre-enhance checkpoint double-applies on baked 2× pixels. A 2nd upscale overwrites the single restorePoint + original snapshot → native original permanently lost that session. Spec acceptance #4 unmet. Only the single-level Revert button recovers the original, and only once.

  • Identity-by-default correctly implemented (enabled:false) — no auto-processing surprise on load; only Apply activates the chain.
  • Transactional safety better than the plan: restorePoint committed only after the worker resolves, plus an inFlight guard — a worker failure leaves the working image untouched.
  • Worker plumbing correct: throwaway copies avoid detaching live buffers; per-run listener removal; single lazy worker.

Root cause & the decision

C1 and C2 share one root cause: a pixel-baking, dimension-changing operation was dropped into a pipeline whose export, persistence, and History are all param-based and re-decode from file. The Sharpen path fits that model perfectly (it's params); the Upscale path fundamentally doesn't. Fixing Upscale means giving the app a notion of a "baked source" that export/persist/History read from instead of re-decoding — a real chunk of work that wasn't in the Phase-1 spec.
